# 말하는 서술형 수학 노트 — 프로젝트 현황

초등학생이 수학 문제를 **말+필기(화면 녹화)** 또는 **사진**으로 제출하면 **Gemini AI가 서술형 채점/피드백**을 해주는 웹앱. 학원 판매를 목표로 하며, 반/학생/숙제 관리와 선생님용 문제은행 기능까지 포함된 단일 HTML 파일 프로토타입.

- 파일: `math-speak-demo.html` (React 아님, 순수 HTML/CSS/JS 한 파일)
- 보안 규칙: `firestore.rules`, `storage.rules` (Firebase 콘솔에 붙여넣어 게시)
- 규칙 테스트: `tests/` (Firebase 에뮬레이터로 규칙 43개 검증 — `cd tests && npm install && npm test`, Java 필요)
- 배포 없이 브라우저로 파일을 직접 열면 바로 작동함
- **claude.ai 아티팩트 미리보기 안에서는 외부 API 호출(Gemini, Firebase)이 CSP로 차단됨** → 반드시 파일을 다운로드해서 로컬 브라우저로 열어서 테스트해야 함

## 기술 스택
- 프론트엔드: Vanilla JS, Canvas API(필기), MediaRecorder(화면+음성 녹화), getUserMedia
- AI 분석: Google Gemini API (`gemini-2.5-flash`, `generateContent`) — 브라우저에서 직접 호출, API 키는 사용자가 입력해서 `localStorage`에 저장
- 서버/DB: Firebase (Auth + Firestore + Storage), compat SDK를 `<script>` 태그로 로드 (빌드 도구 없음)
- 스타일: 토스(Toss) 스타일 — 블루(#3182F6) 계열, 큰 라운드, 그림자 카드

## 현재 구현된 기능

### 학생 화면
- 앱 최초 진입 시 **초대코드 + 이름**으로 반에 참여 (ClassCard 벤치마킹). 초대코드는 모든 학원에서 겹치지 않고, 코드만으로 그 학원·반을 찾아감. 한번 참여하면 `localStorage`에 `{academyId, classId, studentId, name, inviteCode, uid}`로 저장되어 다음부턴 자동 로그인
  - 학생 기기는 **Firebase 익명 로그인**(화면에 안 보이게 자동)으로 서버에 접속하고, 참여 시 `members/{내 uid}`에 등록됨. 보안 규칙이 초대코드가 진짜 그 반 것인지 확인
  - 같은 이름으로 다시 들어오면 같은 학생으로 인식 (학생 ID = 반+이름 기반이라 다른 기기에서도 같은 학생으로 묶임)
  - 기기의 익명 계정이 바뀌면(예: 같은 기기에서 선생님이 로그인했다 로그아웃) 저장해 둔 초대코드로 조용히 다시 등록
  - 선생님이 명단에서 빼면, 그 기기는 다음 접속 때 "반 등록이 해제됐어요" 안내와 함께 초대코드 입력 화면으로 돌아감
- 로그인하면 **내 숙제**가 최상단에 표시, 완료 여부(✅) 표시
- "전체 문제 둘러보기"로 학년-학기/단원별 전체 문제도 탐색 가능
- 문제 풀이 화면: 문제 설명 → 캔버스(문제 식/도형이 미리 그려져 있고 그 위에 직접 필기) → 도구(펜 색상/지우개) → 제출
- 제출 방식 2가지, 문제 학년에 따라 기본값이 갈림(3학년 이하는 사진, 이상은 녹화):
  - **🎥 화면 녹화**: 캔버스 화면 + 마이크 음성을 함께 녹화(`canvas.captureStream` + `getUserMedia`) → Gemini에 영상 전송
  - **📷 사진 채점**: 종이에 쓴 답안을 사진으로 찍어 업로드 → Gemini에 이미지 전송
- 제출 전 녹화본/사진 미리보기 가능
- AI 분석 결과: 🌟 잘한 점 / 💡 생각해볼 점 형식, 문제별 평가기준(rubric)에 맞춰 프롬프트 구성

### 선생님 모드 (헤더의 "선생님 모드" 버튼)
- **학원 계정 로그인** (Firebase Auth 이메일/비밀번호): "새 학원 등록" 탭에서 학원 이름+이메일+비밀번호로 가입 → 계정 1개 = 학원 1개. 로그인하면 **그 학원의 반·문제·제출물만** 보임. 비밀번호 재설정 메일, 로그아웃 지원
  - Firebase를 못 쓰는 환경(오프라인/미리보기)에선 로그인 없이 "우리 학원 (이 기기)"로 바로 들어가고 이 브라우저에만 저장
  - **예전 데이터 가져오기**: 학원 분리 전 버전을 쓰던 브라우저에서 처음 로그인하면, 그 브라우저에 남아 있는 예전 반/문제/제출물을 새 학원 계정으로 옮길지 한 번 물어봄. 초대코드는 그대로 유지(다른 학원과 겹치면 새로 발급)
- **문제 관리**: 기본 제공 문제(3-1 학기 1~6단원, 총 8문항) + 직접 추가한 문제. 추가/수정/삭제 가능. 기본 문제는 삭제는 안 되고 "숨기기"만 가능
  - 문제 필드: 학년-학기, 단원, 제목, 캔버스에 표시할 식/텍스트, **도형(triangle/square/circle) 선택**, 문제 설명, 힌트(칩), 평가기준(잘한 점/생각해볼 점)
- **반 관리**: 반 생성(초대코드 자동 생성) → 반 상세에서:
  - 초대코드 표시 + 복사 버튼
  - **AI 자동채점 켜기/끄기 토글** (꺼두면 학생은 제출만 하고 AI가 채점 안 함 → 선생님이 직접 확인)
  - 학생 명단 관리 (선생님이 직접 넣은 학생 + 초대코드로 들어온 학생을 합쳐서 보여줌. ✕로 빼면 그 학생 기기 등록도 삭제)
  - 숙제 내주기(문제 지정)
  - 숙제 현황(학생별 완료 ✅/⭕)
  - **📥 제출함**: 학생이 제출한 캔버스 스냅샷/사진 + AI 피드백(또는 "선생님 확인 대기") 확인. 클릭하면 상세화면(이미지 또는 영상 재생)

## Firebase 연동 상태
- `firebaseConfig`는 파일 안에 하드코딩되어 있음 (프로젝트: `math-speak-academy`)
- **데이터 구조 (학원별 분리)**
  - `academies/{학원ID}` — 학원 정보 `{name, ownerUid, ownerEmail, createdAt, legacyChecked}` (학원ID = 선생님 계정 uid)
  - `academies/{학원ID}/data/{classes|customProblems|hiddenBase}` — 선생님이 관리하는 목록, 각각 `{list: [...]}` 통짜 저장. **선생님만 수정 가능**
  - `academies/{학원ID}/members/{uid}` — 학생 기기 등록 `{classId, studentId, name, inviteCode, joinedAt}`
  - `academies/{학원ID}/completions/{반__학생__문제}` — 숙제 완료 **1건 = 문서 1개** (`uid` 포함)
  - `academies/{학원ID}/submissions/{sub-시각}` — 제출물 **1건 = 문서 1개** (`uid` 포함). 선생님 제출함은 최근 300개를 불러옴
  - `inviteCodes/{코드}` — `{academyId, classId}` 초대코드 색인 (학생이 코드로 학원을 찾는 용도)
  - 예전 공용 `academy` 컬렉션은 더 이상 안 씀 (새 규칙에서 접근 차단)
- **Auth**: 선생님 = 이메일/비밀번호, 학생 = 익명. ⚠️ **Firebase 콘솔 > Authentication > 로그인 방법에서 "이메일/비밀번호"와 "익명"을 둘 다 사용 설정해야 함** (안 하면 가입/참여 시 안내 메시지가 뜸)
- **보안 규칙** (`firestore.rules` / `storage.rules`를 콘솔에 게시해야 함):
  - 비로그인 접근 차단. 학생(익명)은 등록된 학원의 문제·반·숙제 읽기 + **자기 반·자기 학생 ID·자기 uid로 된 완료기록/제출물 쓰기**만 가능
  - 학생은 반 명단·문제은행을 못 고치고, 제출함(남의 답안)과 학생 등록 목록을 못 읽음
  - Storage: 등록된 학생이 `academies/{학원ID}/submissions/{내 uid}/` 폴더에만 영상/사진(50MB 이하) 업로드. 파일은 본인과 그 학원 선생님만 열람
  - Storage 규칙이 Firestore의 학생 등록을 확인하므로(`firestore.exists`), **Storage 규칙을 처음 게시할 때 콘솔이 묻는 "Firestore 접근 권한 부여"를 허용해야 함**
- **실시간 동기화**: `setActiveAcademy(학원ID, 역할)`이 지금 보는 학원을 역할별로 구독 — 선생님: 반·문제 + 전체 완료기록 + 제출함 + 학생 등록 / 학생: 반·문제 + 내 완료기록 / 둘러보기: 반·문제만
- **Firebase가 없거나 연결 실패해도 앱이 안 죽도록** 방어 처리됨 — 항상 `localStorage`를 기본으로 쓰고(학원별 키 `ac_{학원ID}_*`, 오프라인 학원은 예전 키 `academy_*` 그대로), Firebase는 있으면 추가로 동기화하는 이중 구조 (`saveData` / `syncToFirestore` 참고)
- **Storage**: 코드는 다 넣어뒀음(`uploadToStorage`, 경로 `academies/{학원ID}/submissions/{uid}/{시각}`). Blaze 요금제 전환 여부 아직 확인 필요. Storage 없어도 업로드만 조용히 실패하고 캔버스 스냅샷/썸네일로 대체되므로 앱은 정상 작동

## 알려진 한계 / 다음 우선순위
1. ~~여러 학원 계정 분리~~ / ~~학생 익명 로그인~~ / ~~제출·완료기록 동시 쓰기~~ / ~~제출함 150개 상한~~ — **완료**. 남은 보완점:
   - **초대코드 = 입장권**: 코드를 아는 사람은 누구나 그 반 학생으로 등록할 수 있고, 이름만 같으면 그 학생으로 인식됨(학생 비밀번호/PIN 없음). 코드가 새면 반 초대코드를 새로 발급하는 기능이 필요 (아직 없음)
   - 명단에서 뺀 학생도 초대코드를 다시 입력하면 다시 들어올 수 있음 (막으려면 코드 재발급)
   - 학원 1개 = 선생님 계정 1개. 한 학원에 선생님 여러 명은 아직 불가
   - 선생님 제출함은 최근 300개까지만 불러옴 (더 오래된 건 서버엔 있음. 필요하면 "더 보기" 페이지 기능 추가)
   - 같은 기기에서 선생님으로 로그인한 채 학생 화면을 쓰면, 학생 제출이 선생님 계정 uid로 기록됨 (실사용에선 기기가 달라 문제 없음)
2. **API 키가 브라우저에 노출됨** — 지금은 사용자가 직접 Gemini API 키를 입력해서 localStorage에 저장하는 방식. 여러 학생에게 무료 배포하려면 Cloudflare Workers 등으로 프록시 서버를 만들어 키를 숨겨야 함 (아직 미구현, 논의만 된 상태)
3. **반 삭제/이름 수정 기능 없음** (반을 지울 땐 `inviteCodes/{코드}` 문서도 함께 지워야 함) — 한번 만든 반은 못 지움
4. **학생 여러 명 한번에 추가(붙여넣기) 기능 없음** — 한 명씩만 입력 가능
5. **선생님 화면에 대시보드(전체 요약 통계) 없음**
6. Gemini API 응답 편차 관련 논의됨 — `temperature` 파라미터가 코드에 아직 미설정(기본값 사용 중). 필요하면 `generationConfig: { temperature: 0.2 }` 추가 고려
